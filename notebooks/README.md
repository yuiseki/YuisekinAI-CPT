# One notebook per model

Each file here is the notebook that was uploaded to Colab to produce the
model it is named after. They are generated by `tools/mk_notebook.py` and are
self-contained: flattened copies of `src/` rather than a checkout, so a run
needs nothing but the notebook and the published datasets.

| notebook | model | corpus |
|---|---|---|
| `qwen3-0.6b-base-jp-gov-v0.1.ipynb` | [`yuiseki/qwen3-0.6b-jp-gov-v0.1`](https://huggingface.co/yuiseki/qwen3-0.6b-jp-gov-v0.1) | 1,632 facts from `yuiseki/geo-triples-jp-gov`, said eight ways |

The name is the base model, the data, and the version: the notebook says what
went in, and the model repository says what came out. The scores of each run
are in `tmp/scores/`.

A notebook here is a record of a run that happened. Regenerating one rewrites
that record, so a change to `tools/mk_notebook.py` meant for the next run
should write the next file rather than overwrite the last one:

    python3 tools/mk_notebook.py notebooks/qwen3-0.6b-base-jp-gov-v0.2.ipynb
